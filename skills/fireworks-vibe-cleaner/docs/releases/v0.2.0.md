# v0.2.0 — approved archive removal and Jev guidance

Adds removal of explicitly approved, verified archived transcripts and original-path byte recovery. Jev configuration is recommended up front; all cleanup still requires human confirmation.

## Changes

- Add archive-plan/apply/verify/restore for narrowly recognized old main transcripts. Plans verify actual archive bytes; exact approval, stopped writers and explicit history-risk acknowledgement precede source removal.
- Restore exact bytes at original paths with new inodes allowed. Related files and indexes remain unchanged; native continuation is unverified.
- Exclude subagent, sidechain, fork and unknown-origin transcripts, tool results, checkpoints and assets from removal.
- Recommend secure Jev configuration first; retain rules-only fallback. Jev suggests keep/review/backup/delete from locally allowed choices and has no execution authority. Delete suggestions are restricted to old logs/rebuildable caches.
- Keep log/cache quarantine and separately approved purge as an independent flow.

The preserved 2026-09-21 experiment covered 564 files and 10.181 GiB of original sessions, with 5.308 GiB of archives and 564/564 byte checks matching. Originals remained and actual cleanup reclaimed zero bytes. Four earlier live Jev calls used 11,141 input tokens; all 60 comparison decisions were review. Those historical results do not prove the new removal flow or delete-advice quality. See both READMEs for the unchanged detailed tables and native-reader failures.

Before approving archive removal, users must understand that history can become unavailable. File restoration does not rebuild application state or prove continuation. Preserve archives, manifests and journals. Cross-volume moves and encrypted backups remain unavailable.
