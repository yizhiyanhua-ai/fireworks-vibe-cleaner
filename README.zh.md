在 Codex 或 Claude Code 里用自然语言检查日志、会话和缓存，让 Jev 辅助判断处理方式，再由你确认具体方案后执行。推荐安装后优先配置 Jev；选择纯规则模式也可继续使用。

**清理前必须人工确认具体方案。** v0.2.0 支持先校验已有归档，再移除获准处理的旧主会话原件，并可恢复到原路径。文件字节恢复不代表原生续聊已经验证。

## 在 Codex / Claude Code 里怎么用

### 1. 安装后，优先配置 Jev

> 帮我从 https://github.com/yizhiyanhua-ai/fireworks-vibe-cleaner 安装 v0.2.0，放到当前工具的个人 Skill 目录。不要覆盖已有安装，也不要清理文件。然后指导我安全配置 Jev。

需要 macOS/Linux 和 Python 3.11+，也可参考[手动安装指南](docs/cli.zh.md#安装)。Jev 使用 `TYPESAFE_API_KEY`，通过密钥管理器或进程环境安全注入，不要把 Key 粘贴到聊天、报告或命令历史。`doctor` 只检查 Key 是否存在，不代表鉴权或推理调用成功。

> 联网调用前，先说明 Jev 接收哪些信息、是否可能收费。如果我选择纯规则模式，就不配置 Key，继续本地检查。

推荐使用 Jev 辅助建议，实际联网仍需授权。它只接收类别、大小与年龄区间等元数据，不发送路径、文件名、会话正文或代码。建议分为**保留、待复核、备份、删除候选**；只有通过本地检查的旧日志或可重建缓存，且打开句柄检查无异常时，才提供删除建议。打开句柄快照不能证明写入进程已经停止。Jev 没有批准或执行删除的权限；缺 Key 或服务故障时退回本地规则。

### 2. 检查空间，再看辅助建议

> 用 fireworks-vibe-cleaner 检查 Codex 和 Claude Code 的占用，列出主要来源和必须保留的内容。对选定候选检查本地活跃状态；如果我已经授权调用，就让 Jev 辅助判断备份、保留、复核或考虑删除。先给我看结果，不要移动或删除文件。

项目根需要明确指定。扫描不代表整盘统计，跳过的目录和无法读取的文件必须说明。活跃状态未知、受保护对象和凭据，都不能通过模型建议获得删除权限。

### 3. 确认具体方案后再执行

> 给我看具体文件、处理方式、占用大小、恢复限制和计划哈希，等我确认这份方案再执行。如果要处理已经归档的会话，还要说明历史记录可能不可用，恢复文件字节不代表可以继续对话。

两种清理流程相互独立：

- **旧日志与缓存：**先批准隔离，验证后可恢复，或另行批准永久清理。同盘隔离释放 **0 字节**。
- **已经备份的主会话记录：**`archive-plan` 校验已有归档与所选源文件字节。取得具体计划批准、停止写入并明确确认历史风险后，`archive-apply` 才移除这些原件，保留归档。关联文件与 harness 索引均不修改。

“帮我清理”不代表批准未知文件。修改前必须停止相关写入；`--writers-stopped` 是确认声明，不会替你关闭进程。文件或范围变化后需要重新生成计划。

## 还可以这样说

| 想做什么 | 发给 AI 的话 |
| --- | --- |
| 检查项目 | “检查 `<项目绝对路径>`，只报告占用，不改文件。” |
| 保留重要数据 | “保留最近 30 天和 `<需要保留的路径>`，列出剩余候选。” |
| 备份会话 | “备份所选旧会话，校验字节，原件保留。” |
| 移除已归档原件 | “为这些主会话准备归档后移除计划。检查已有备份，说明范围和历史风险，等我确认。” |
| 恢复会话原件 | “将已批准的归档移除记录恢复到原路径，不覆盖已有文件，不宣称可以继续对话。” |
| 撤销隔离 | “恢复已批准的日志/缓存隔离，遇到冲突不要覆盖。” |

`archive-restore` 恢复原路径和精确字节，新 inode 属正常现象；它不重建索引，也不恢复完整 harness 状态。请保留归档、manifest 和事务日志。仅备份会保留原件并增加占用。

## 支持范围

| 内容 | v0.2.0 行为 |
| --- | --- |
| Codex `log/codex-tui.log`、`logs/codex-tui.log`；Claude `debug/` 日志 | 已识别、超过保留期的普通文件可先批准隔离，再单独批准永久清理 |
| Python `__pycache__/*.pyc` | 源文件必须被 Git 跟踪，缓存被忽略且未被跟踪 |
| 已识别的旧主会话记录 | 先备份；另行生成归档移除计划，确认具体范围与历史风险后才能移除 |
| 子代理、sidechain、fork、未知来源会话；工具结果、检查点、资产 | 不移除原件；符合支持范围时仅可备份 |
| Worktree、源码、记忆、凭据、数据库与未知对象 | 不自动删除 |

完整命令见[CLI 指南](docs/cli.zh.md)，另见[兼容说明](docs/compatibility.md)与 [v0.2.0 证据记录](docs/releases/v0.2.0.md)。本地报告与恢复文件请私下保存。

## 真实 10 GiB 验证与 Jev 线上对比

以下是此前的备份实测，早于 v0.2.0 的归档移除流程与扩展 Jev 选项，不能作为这些新能力的实测结果。

**真实数据清理必须先经过人工确认，确认内容须包含具体范围和操作。** 本轮仅读取原件、创建私有归档并校验恢复字节，没有隔离、移动或删除任何原始文件。

实测日期：2026-09-21。选取 **564 个已有会话文件，共 10,932,021,589 字节（10.181 GiB）**；Codex 样本至少 7 天未修改，Claude 样本至少 1 天未修改。选择时检查了打开句柄，并冻结全文哈希。源目录盘点跳过 227 个边界，不能视为完整磁盘统计。

| 真实数据集 | 文件数 | 原始字节 | ZIP 字节 | 归档体积缩小 | 全量解压 / 最后原件哈希 |
| --- | ---: | ---: | ---: | ---: | --- |
| Codex 历史会话 | 560 | 9,932,261,559（9.250 GiB） | 5,447,045,764（5.073 GiB） | 45.16% | 全部一致 |
| Claude 历史会话 | 4 | 999,760,030（0.931 GiB） | 252,487,818（0.235 GiB） | 74.75% | 全部一致 |
| **总计** | **564** | **10.181 GiB** | **5.308 GiB** | **47.86%** | **564/564 一致** |

全部 **1,107,896 条非空 JSONL 记录**通过解析，非法行和超限行均为 0。所有归档都已全量流式解压并做 SHA-256 校验，没有覆盖正在使用的 harness 目录。原件与 ZIP 的逻辑大小差为 **4.873 GiB**；由于原件保留，**实际清理释放仍为 0 字节**，归档和保留的校验副本会增加占用，不能把这个差值当作磁盘回收承诺。过程中曾主动暂停一次，增加单条 JSONL 行长度上限 64 MiB（不等于进程总内存上限），之后复用 1 个完成的分卷续跑；耗时和卷空闲量变化仅对应续跑阶段，不作为冷启动性能基准。
