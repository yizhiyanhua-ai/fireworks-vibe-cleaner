# v0.4.0 — Jev-first explainable triage

The earlier advisor did not explain why a particular transcript should enter a removal proposal. The new `triage` command lets Jev choose an action and its bounded reason together, then shows every selected file, alternatives, local facts and unknowns directly in the terminal. The Skill requires the same inline presentation in chat.

- Backup retains originals. Conditional removal preparation requires later verified backups, protection/activity checks and exact human confirmation. Triage never creates an executable plan or removes files.
- Eight files per request, up to three concurrent requests, at most 100 candidates. Explicit per-item fallback and low-confidence review; no retries, paths or content sent to Jev.
- Real 33-file, 1,049,047,931-byte comparison: serial 10,070 ms; concurrent 3,461 ms. Ten real calls in total. Both complete source-hash comparisons passed; zero originals changed and zero bytes reclaimed.
- Recommendations differed: serial 33 review; concurrent 5 prepare-removal and 28 review. These observations establish neither accuracy nor stable speedup.

See [sanitized live evidence](../experiments/real-jev-triage-2026-09-22.json), [design and limits](../jev.md), and the bilingual README. Tests use isolated fixtures; paid live checks are opt-in and never run in CI.
