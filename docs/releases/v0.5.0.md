# v0.5.0 — Fresh evidence before Jev decisions

Triage now distinguishes backup references from selected-byte verification, reads fresh selected Codex index/header facts, and observes open handles in batches. Current, pinned, linked, open and otherwise protected objects are retained locally before provider calls. Recovery requirements stay unknown unless explicitly supplied.

- Existing backup verification is opt-in with a logical read budget; it never claims whole-archive or native-resume recovery. Corrupt members fail individually.
- Matching unverified copies can receive a verify-existing-backup suggestion; verified selected copies can be reused. Transcript removal preparation requires all evidence gates plus an explicit file-copy recovery preference. It remains non-executable advice; exact-plan human approval is still mandatory.
- Real comparison: 14 existing files, 404,874,193 bytes, 10 evidence patterns. Two repetitions took 1,459/1,405 ms including 329 ms of fact collection, versus 1,060 ms for v0.4.0 on this sample. Both new runs produced 5 local keeps and 9 reviews. Unknown recovery requirements closed removal preparation.
- Raw Jev choices matched for 9/9 candidates; this is not a calibrated accuracy or consistency claim. One initial batch failed with an unresolved generic status; all attempts are retained and fixed-code diagnostics are now available.
- Nine checked source hashes remained unchanged. Five protected/dynamic files were not hashed. No source cleanup, native continuation or reclaimed space is claimed. Real pinned/cache cases and the explicit archive-copy removal-preparation branch remain uncovered.

The [sanitized comparison](../experiments/real-jev-evidence-2026-09-22.json) and bilingual README separate local protection, model choices and confidence overrides. This release strengthens evidence and gates; it does not establish accurate backup-versus-delete allocation or a speedup. Synthetic engineering tests are separate from real-data validation.
