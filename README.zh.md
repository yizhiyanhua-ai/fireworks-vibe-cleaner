fireworks-vibe-cleaner 是 **Skill + CLI**：你在 Codex 或 Claude Code 里用自然语言说明需求，Skill 负责检查和解释，CLI 负责确定性扫描、校验、执行与恢复。任何真实清理都要先把具体清单、方法、影响和计划哈希给你看，得到确认后才执行。

## 三句话开始使用

### 1. 安装，并优先配置 Jev

> 帮我安装 fireworks-vibe-cleaner，仓库是 https://github.com/yizhiyanhua-ai/fireworks-vibe-cleaner 。检查环境和已有安装，不要直接覆盖，也不要清理文件。安装后指导我安全配置 Jev；如果我暂不配置，先用本地规则检查。

支持 macOS/Linux，需要 Python 3.11+。手动安装见 [CLI 指南](docs/cli.zh.md)。Jev 通过固定元数据辅助筛选，不接收路径、标题、会话正文或代码；联网前应说明发送范围和可能费用。不要把 API Key 粘贴进聊天或命令历史。

### 2. 先看清单，把保留需求说清楚

> 检查 Codex 和 Claude Code 占用了多少空间。直接在聊天里列出候选、处理建议、原因、备选方式、预计影响和不确定项。正在使用、有关联、我指定保留或判断不清楚的内容不要动。先给建议，不要删除。

重要会话可以直接说“这些以后还要接着聊”；只需要文件副本时，可以说“这些会话保留一份验证过的归档就够了”。需求没说清楚时保持未知。Jev、规则和本地助手都只能提供建议，不能替你批准清理。

### 3. 看完方案，再批准这一次操作

> 把具体文件、处理方式、备份位置、预计释放空间、恢复限制和计划哈希给我看，再附完整计划。等我确认这份方案后执行，执行完成后报告实际结果。

执行前必须停止相关写入。计划过期但文件和归档没变时，`archive-refresh` 会重新校验同一范围并生成新哈希，仍需重新确认。大批量清理推荐 `archive-workflow-*`：先移除并恢复 1 个金丝雀文件，原路径和字节校验通过后，CLI 才允许进入正式清理。

## 备份、归档和清理有什么区别？

| 操作 | 原件和空间会怎样 |
| --- | --- |
| 备份 | 新建或复用副本，原件保留；新增副本会占空间 |
| Codex 历史归档 | 调整历史列表显示，预计释放 0 字节 |
| 日志/缓存隔离 | 先移入同盘隔离区，可以恢复；隔离本身不释放空间，永久清理需另行确认 |
| 移除已备份的会话原件 | 先校验归档，再移除你批准的原件；可恢复文件字节，但原生续聊仍未验证 |

全部 **1,107,896 条非空 JSONL 记录**通过解析，非法行和超限行均为 0。所有归档都已全量流式解压并做 SHA-256 校验，没有覆盖正在使用的 harness 目录。原件与 ZIP 的逻辑大小差为 **4.873 GiB**；由于原件保留，**实际清理释放仍为 0 字节**，归档和保留的校验副本会增加占用，不能把这个差值当作磁盘回收承诺。过程中曾主动暂停一次，增加单条 JSONL 行长度上限 64 MiB（不等于进程总内存上限），之后复用 1 个完成的分卷续跑；耗时和卷空闲量变化仅对应续跑阶段，不作为冷启动性能基准。
