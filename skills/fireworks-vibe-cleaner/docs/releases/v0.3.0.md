# v0.3.0 — Codex history pressure and reviewed native archive

Codex histories can grow in both bytes and list length. This release adds configurable pressure checks and a separately approved native archive workflow, including spawned descendants and individual recovery.

- `history-audit`: read-only, recognized `state_5.sqlite` schema, bounded metadata-header checks. Defaults: readable indexed total or single-file size above 3 GiB, or unarchived count above 200.
- `history-plan`, `history-apply`, `history-verify`, `history-restore`: complete-audit and exact-hash gates, stopped-writer acknowledgement, bound native executable, full descendant closure, durable intent, byte/path/membership verification and separate recovery approval.
- Keep the newest 100 unarchived threads, updates within 30 days, pinned/current and explicitly retained IDs. Any protected descendant blocks its root. Incomplete audits and destination conflicts, including dangling symlinks, refuse execution.
- Require a chat overview before the full plan link and human confirmation. Native archive promises **zero disk reclaim**. Verified-ZIP source removal remains a separate authorization.
- Initial native writes support **macOS and codex-cli 0.154.0** only. OS rules deny network, execution of other programs and writes outside CODEX_HOME/private runtime HOME. The native program still reads Codex configuration and maintains its index. Unknown launchers or versions refuse writes.

The native archive API cascades through descendants. Unarchive handles one ID at a time and updates file mtime/index update times; restoration does not promise original timestamps. New lineage, changed content or occupied paths can prevent automatic recovery and require manual inspection. Other writers must be stopped; a new app-server's `notLoaded` state is not global activity evidence.
